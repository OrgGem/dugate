## 2. Infrastructure Gating & Isolation Protocol

### 2.1 The Two-Phase Testing Model
1. **OFFLINE Phase (Zero Infrastructure):**
   - Pure unit, contract, schema, AST parsing, and in-memory mock suites.
   - Requires NO Docker containers, NO ports, NO locks, NO database credentials.
   - Completely safe to execute concurrently across multiple development lanes without contention.
2. **LIVE_INFRA Phase (Gated by Shared DB Window):**
   - Requires PostgreSQL on `127.0.0.1:5433` and/or Redis on `127.0.0.1:6380`.
   - **Gating Rule:** Must NEVER execute until the shared DB window is officially released by the platform lane (Claude Code) in `du-rework/coordination/reports/claude.md` with literal `'DB RELEASED'`.
   - **Claim Rule:** The testing lane claims the window in writing via `reports/antigravity-6.md` with `DB CLAIMED`.
   - **Isolation Rule (MM-13):** Every live suite must run with per-run schema isolation (`TEST_RUN_ID=<run_id>`, `REDIS_DB_INDEX=<index>`), preventing global `TRUNCATE` collisions and table locking contention.
   - **Release Rule:** The testing lane immediately writes `DB RELEASED` when execution concludes.

## 5. Execution Guide: Unified Batch Runner

The testing runner `du-rework/tests/isolation/concurrent-runner.ps1` has been expanded to provide a single, unified execution interface ("chạy tập dưới một nhãn") with built-in MM-13 isolation harness support.

### 5.1 Running the Offline Suite Batch (Zero DB / Safe)
```powershell
# From repository root or du-rework directory:
.\du-rework\tests\isolation\concurrent-runner.ps1 -Mode Batch -Category Offline
```
- Executes all 81 offline suites.
- Does NOT require PostgreSQL or Redis.
- Safe to run at any time regardless of DB window ownership.

### 5.2 Running the Live Suite Batch (Gated & Isolated)
```powershell
# Prerequisite: Claude Code has written "DB RELEASED" in reports/claude.md
# Testing lane has recorded "DB CLAIMED" in reports/antigravity-6.md
.\du-rework\tests\isolation\concurrent-runner.ps1 -Mode Batch -Category Live
```
- Allocates dynamic MM-13 isolation sandboxes (`TEST_RUN_ID`, `REDIS_DB_INDEX`, schema `du_test_<runId>`).
- Executes all 23 live suites sequentially without cross-run data corruption or table locks.
- Collects and prints literal `'Tests: N passed, M total'` per suite.

### 5.3 Running Concurrent Isolation Verification
```powershell
.\du-rework\tests\isolation\concurrent-runner.ps1 -Mode Concurrent -TargetSuite "tests/runtime.test.ts" -OffsetSeconds 5
```
- Proves that two overlapping test runs execute concurrently with zero cross-run cleanup and zero contention.
