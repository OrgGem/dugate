## Desired contract

Catalog belongs to Orchestrator repository/platform control plane; secret material stays in the approved managed store. Entries: stable secretId, tenant/scope, unique display name, purpose/service permissions, provider, state/revision, rotation metadata and usage references. Names are display labels, references use immutable IDs, rename never rebinds consumers.

Sources: managed_value (write-only creation/rotation into approved Vault KV2 or existing encrypted secret backend) or vault_reference (configured trusted Vault connection ID, mount, logical path, field, optional namespace and explicit version mode pinned/latest). Two-level choice (no per-secret DB-vs-Vault toggle): the user picks managed_value vs vault_reference per secret only; which backend backs managed_value (Vault KV2 vs existing encrypted store) is a deployment-level decision and MUST NOT be exposed as a Portal toggle. vault_reference may only use an operator-approved connectionId/mount scope; the user supplies only the locator (mount/path/field/version) within the allowed scope. Path is a secret locator, not a content hash and not an arbitrary HTTP endpoint. Vault namespace/version support is provider-capability gated. Reuse tenant-bound Connector path rules; importing a link cannot bypass account/revision fences. Validate allowed mounts/path scopes/field and read permission server-side with safe probe, no resolved value returned. Missing Vault writer means explicit unavailable, never pretend Save works. Vault Transit encryption keys are distinct from KV credential values.

**Sources note:** `managed_value` backend (Vault KV2 vs encrypted store) là quyết định deployment-level, không phải lựa chọn per-secret của user; Portal không expose toggle này. `vault_reference` chỉ dùng connection đã được phê duyệt; user chỉ nhập locator (mount/path/field/version) trong scope cho phép.

Shared ValueSource tagged union: literal or secret_ref, no ambiguous strings or implicit vault:// parsing. Schema decides whether each field accepts either mode; fields requiring literals, such as selectors and restricted endpoint origins, must not become arbitrary secret-supplied URLs. Selector offers Text value and Secret, searchable permitted catalog entries, name + Secret badge + masked reference/state metadata; switching type requires an intentional replacement, never prefill resolved value. Literal credentials are password-style write-only inputs and MUST be encrypted/secret-managed before persistence, even though user chose Text. Ordinary non-sensitive literals can be displayed. Edit secret fields shows configured/replace/clear, never decrypted old value; omitted update preserves, explicit clear is separate. Masking is not storage encryption. No credential values in HTML, API readback, browser persistent storage, logs, audit or test diagnostics.

Use same selector for approved Connector credentials/provider headers, profile endpoint callback headers/OAuth2 client secret, OIDC secret and supported external source auth/config slots. Do not relax egress rules through resolved headers/URLs. Secrets read/list/create/rotate/link/disable/use permissions are separate; listing name does not grant resolving value. Tenant/platform scope explicit; platform secrets cannot become tenant selectable by default. Usage index prevents unsafe deletion; disable/revoke stops future resolutions including cached ones. Published profiles pin reference/config revision; document rotation latest/pinned semantics and operation retry/resume behavior.

## Runtime resolution

Orchestrator owns metadata and authorization, not a public resolve-to-plaintext API. Trusted service resolves only its approved purpose/reference under authenticated tenant and admitted profile/connector revision. Prefer service-scoped Vault workload identity directly or a tightly restricted internal resolver according to current deployment; architect freezes one actual production route. Never send secret values to worker/browser merely because ID was selected. Connector/callback/OIDC production constructors must receive actual resolvers and consume selected references, not display-only forms. Vault tokens/permissions/renewal are deployment-owned; no broad root token or user arbitrary path access. Bounded memory caches, version/purpose/tenant keys, expiry and rotation invalidation, fail closed on missing/revoked secret or Vault outage, no literal fallback. Internal DU HTTP transport exception unchanged; encrypted persistence required. Runtime health reports safe availability/applied revision only.
