# OR10-03 receipt — runtime lease replay

Date: 2026-10-10

## Change

- `claimTask` now replays a delivery only when the task is `RUNNING`, the
  `leased_by` value exactly matches `workerInstanceId`, and the lease has not
  expired.
- A different worker cannot reuse an active lease, even with the same delivery
  ID. An expired lease follows the normal takeover update, which assigns the
  caller and increments `lease_epoch`.
- `WAITING_INPUT` and `WAITING_CHILDREN` tasks reject stale delivery claims;
  resume/join must first make the task runnable and dispatch it again.
- Added offline regression coverage for valid same-owner replay, a different
  worker with an active lease, expired-lease takeover by either worker, and
  waiting-input/children states.
