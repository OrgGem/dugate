## Minimal contract and ordering

Add `BackupEffectFencePort` behind the existing `MaintenanceBackupFence` adapter. Contract:

- `acquire({backupId,maintenanceJobId,executionToken,expectedFenceRevision,reason})` persists a unique purpose BACKUP fence, requested domains, owner/execution identity, prior control states/revisions and phase ACQUIRING. It closes gate rows atomically with new-effect authorization in each owning DB. Cross-DB acquisition is a durable staged protocol, not an atomic transaction claim.
- `observe({fenceId,revision})` returns owner-collected observations for **each expected replica/boot identity** plus durable domain/effect counts, fresh ACK of that exact fence revision, outstanding write-capability and snapshot evidence. No caller supplies `fenced:true`, zero counters or PASSED. Collector validates actual runtime identity/image/slot, exact source and freshness before adapting to existing proof.
- `prepareSnapshot({fenceId,revision})` establishes immutable DB snapshots and artifact version manifest only after all applicable effects are locally quiescent/evidence-resolved, then records snapshot IDs/digests/watermark and phase SNAPSHOTTING. Gates remain effective through both PG dumps and artifact ciphertext/sidecar copy/hash verification.
- `release({fenceId,expectedRevision,executionToken,restorePriorState:true})` is exact idempotent CAS. Phase and recorded prior state survive process crash. Releasing backup's overlay does not resume independently paused/draining services or overwrite later control changes.

The six domains stay admission, Orchestrator dispatch, provider issuance, Connector invocation polling, artifact mutation and Connector usage delivery. Backed-up stateful Admin/config/credential/generation mutations must also be serialized by their owning snapshot-write gate or proven immutable snapshot/pin closure; freezing only public submit while other producers rotate referenced config is insufficient. Heartbeat/read-only telemetry may continue where it cannot change captured business/artifact/key state, with explicit bounded exclusions. There is no wildcard exclusion for all maintenance traffic.

**Normal DRAINING:** reject new invocation admission and fresh worker work, but allow existing legitimate async polling, completions, checkpoints and usage settlement to finish. A future pending poll is not zero for normal HA retirement. **BACKUP effect fence:** reject all new external effect permits, including future poll and usage delivery attempts, but allow already admitted effects to finish durable settlement. Preserve pending schedules/ledger state; resume them only after fence release. Do not fail/clear PENDING/UNKNOWN or release quota solely to achieve quiescence.

Acquisition order should first close admission/new dispatch and state-mutating configuration/grant issuance, then establish Connector/provider/poll/usage gates and artifact mutation barrier. Already active effects and worker reports complete under tracked ownership. Require authoritative active worker leases0 and settled business writes before snapshot, or explicit immutable-state checkpoint proof rather than an inferred stopped process. If a stage fails, persist the incomplete fence and recovery phase; a blind finally/resume is not sufficient. Failure/cancel can remove only an overlay whose quiescence/snapshot outcome is safely known and restore only its recorded prior state; uncertainty remains HELD/UNKNOWN with operator recovery.

## Durable effect permits and actual counts

Before any external first-send, poll-send or usage sink call, authorize an effect permit under the same DB lock used by backup fence activation. Persist effectId/domain/operation-invocation-or-event identity/replicaId/bootId/fence epoch/owner token/state. State distinguishes PREPARED (can still send), ACTIVE, SETTLING, COMPLETED and UNKNOWN; all nonterminal states remain counted until actual local completion or trusted process/effect reconciliation. Hold bookkeeping through response, ledger/outbox commit and cleanup so zero cannot precede billing/result settlement. Actual send must consume the permit with owner/state/fence CAS immediately before network work. A pre-fence permit racing a fence is counted and awaited; a canceled unstarted permit cannot send later.

**Expiry is not completion.** Missing heartbeat/expired lease/stale ACK/process restart cannot convert ACTIVE or PREPARED to zero. A restarted process has a new boot identity, must observe the held durable fence before any effects, and cannot silently take over an expired effect. Mark uncertain ownership UNKNOWN and require actual stopped prior process/socket/settlement evidence. A locally quiescent unresolved effect may be recorded separately only after trusted proof the old process cannot issue/commit further local work; preserve its remote/business uncertainty and holds. Never infer remote provider inactivity from a closed socket or process exit.

The collector combines durable unclosed permits with fresh per-process actual active counters; neither replaces the other. Both Connector replicas and both applicable Orchestrator/worker replicas must ACK the same held fence with fresh boot identity and actual observed counts. An unobserved expected replica blocks proof unless trusted host evidence establishes it stopped/fenced and no surviving effect can mutate the snapshot. Control GET/ACK and the exact executing backup job are counted separately; no caller-defined counter exclusions.

**Usage outbox:** persist CLAIMED owner replica/boot/token/expiry on claim, CAS markDelivered/defer on that token, and guard both claim and actual sink-send with backup fence/effect permit. Do not release SELECT locks then regard attempt increment as a claim. During normal drain existing sends/retries may settle; while backup held new sends are blocked. Lost sink ACK keeps the same event identity for dedup reconciliation/retry after safe ownership resolution. Do not count lease expiry as no send; retain unresolved delivery evidence. Sink settlement must remain idempotent so replay never doubles usage or quota release.

**Provider/poll:** first invocation claim and pending-poll claim lock the backup row before invocation state. Preserve normal drain distinction: pending poll checks BACKUP gate, not an unconditional DRAINING rejection. Use a consistent lock order fence→replica→invocation/outbox row. Guard actual adapter/provider transport as well as repository claims; an early claim check alone cannot close the delayed-send race. Terminal replay returns frozen result without a new effect and need not contact provider. Neither cancel/timeout nor lease loss rewrites UNKNOWN as FAILED merely for backup.

## Artifact fence: issued capabilities and exact versions

No untracked successful presign may escape. Server-mediated writes keep permits until exact ciphertext+sidecar versions and metadata transaction settle.

Outstanding direct grants require one of these **actual** evidence boundaries:

1. **Write capability closure:** confirmed storage-level revoke/cancel where supported, or expiry plus an evidenced upper bound/termination of already-started uploads. Expiry only stops fresh request authorization; an upload begun before expiry may still finish. Multipart abort must be confirmed and outstanding part writes/complete capability accounted. 2. **Exact immutable-version snapshot:** provider versioning/immutable-version API proves every included READY object and encrypted sidecar is read/copied by a retained exact storage generation+versionId+size/hash; surviving grants cannot change/delete those exact versions. Freeze metadata/reference acquisition and deletion, export pinned manifest inside the DB snapshot, copy/hash those exact ciphertext versions and retain them through copy. Grants targeting STAGING/uncommitted data or creating later versions remain explicitly recorded outside the included snapshot; record their count/expiry, never claim globally no outstanding writers. An unversioned supposedly unique key is not immutable while an issued PUT can overwrite it. No latest-key read, silent snapshot omission or raw DB READY row without corresponding exact bytes.

State the chosen mode in fence/bundle evidence, e.g. `artifactSnapshotMode: capability-closed | exact-version`, outstanding capability counts and included-object pin proof. Adapt artifactMutation.inFlight0 only to the proven snapshot-mutating effect scope; if outstanding grants remain, expose them and the exact reason they cannot alter included versions. Do not call HTTPrequests0 sufficient. Preserved STAGING/multipart state remains nonready in restored data with old source capabilities nonusable; it must not become fabricated complete output or trigger automatic external upload/replay.

All artifact reader/deleter generation/key-version pins and backup retention pins are immutable. Fence guards must include concurrent grant issuance/finalize/cleanup/generation change; restoring or releasing prior state cannot retarget old objects to current storage. Snapshot covers ciphertext and crypto sidecar/manifests; hash/count linkage is checked against each captured PG reference, not a count-only bucket listing.
