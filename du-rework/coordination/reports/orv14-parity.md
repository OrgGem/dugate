## Delivered source and consumer paths

- Identity service/repository carries current local-user role, status, exact key/Profile assignment set, version and safe `legacyPasswordResetRequired` marker. Password reset is a tenant-row lock + expected-version CAS. An imported row is enabled and its marker consumed only when the exact row is disabled, unlocked and marked reset-required; the reset hash, version bump and activation audit commit together. Normal disabled users remain disabled, locked imports are rejected, and role/status writes cannot bypass the explicit reset path. Existing login/session readers require enabled, unlocked, marker-false state and current database version, so the accepted reset path works after the legacy source is off and invalidates old sessions across replicas.
- The Identity UI visibly marks imported reset-required users and gives platform Admin the explicit password activation action. The wire extension is backwards compatible: old payloads parse as `legacyPasswordResetRequired=false`. Safe read DTOs expose no hash, secret, raw key or session token.
- API-key lifecycle implementation provides tenant-scoped server search/status/cursor pages, issue with copy-once raw value, note edit, rotate, revoke, and complete Profile membership replacement, with idempotency/CAS/audit. Protected Global key mutations fail closed. The API Keys screen exports `ApiKeysScreen`; Ops owns its route/nav registration.
- Connector recipe editor has structured provider/URL/method/timeout/model/session/mapping/header/response fields plus strict advanced JSON import/export. Typed revisions are immutable; draft/rollback creation uses expected-head CAS, test is bound to the selected exact revision, and activation requires exact successful test plus expected-current CAS. Credential actions are Keep, write-only Replace, explicit Clear or opaque Secret Catalog UUID. The source is never returned as plaintext or direct Vault path. Backend owns the server-side Secret Catalog validation/import into a new Connector KV-v2 pin; that writer handoff remains open until its actual call path is integrated and tested.
- Provider-test service calls `SubmissionService.admitProviderTest` and uses its exact tenant/key/Profile/business/action/parameter/artifact admission pins. It signs a dedicated exact-revision Connector test grant, creates durable synthetic operation/task/run rows, invokes only the Connector runtime, and uses Connector cost preflight and evidence. Local USER requires the exact active assigned key and Profile binding; a platform Admin (including validated local ADMIN) may use a temporary manifest-checked binding-slot overlay to test a PENDING candidate. Normal grants/Profile state are not modified. UNKNOWN remains in concurrency capacity; retries use the same idempotency identity and only persisted Connector success plus its linked usage event can settle UNKNOWN.
- Connector result projection retains bounded content only when the Connector's credential-aware persisted sanitizer sets `contentSanitized: true`. The Connector sanitizer removes the resolved credential, actual outbound header values and sensitive config values; unmarked legacy content is withheld.
- Connector management store exports `getConnectorSignalSnapshot({tenantId,from,to})` and calls the signed, tenant/window-fenced Usage producer `/internal/admin/signals/usage` with `connector:signals:read`. The typed result is wired for the Ops/incident consumer; no synthetic readiness/config projection is used.
- Recipe override compiler exports `compileConnectorRecipeOverrides` and `compileConnectorRecipePins`; it produces strict immutable `{connectorId,connectorRevision,recipeDigest,staticFormFields,extraHeaders}` pins only from bounded declared static fields and safe headers. Journeys consumes per-node pins at invocation.

## Compatibility and security decisions

The legacy-password compatibility path uses the complete mapped-reset alternative accepted by canonical compatibility review §125. It does not archive bcrypt material, add a metadata-encryption slot, or need migration 0058. Continuity readiness must count all reset-required users and keep cutover readiness incomplete until zero. Required source-off login and scoped-BFF proof remains an independent continuity receipt.

Credential `vault-ref` accepts a Secret Catalog ID UUID only. It rejects caller-supplied Vault coordinate JSON/path. The trusted importer must resolve the record under the authenticated tenant, require ACTIVE `connector.credential` permission for the Connector service, and create/persist a fresh immutable required-version Connector KV-v2 source pin. It must journal source ID/provenance/idempotency and never return values or Vault paths.

Mutation policy: validated platform Admin (including local ADMIN) writes Identity, keys and Connector revisions; tenant operator can use only currently allowed tenant-scoped reads; viewer has no parity read/write; local USER is read-only for these administration resources and can invoke only the separately admitted exact active provider test and exact assigned operation scope. PENDING candidates are platform-Admin only. CSRF, trusted session context, tenant fencing, idempotency, CAS and audit are server-side requirements.
