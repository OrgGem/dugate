## 0. TL;DR

- `matchSecretsRoute('/secrets')` là method-agnostic nên luôn trả `{ kind: 'list' }`; `handleSecretsRoute` cũ tính `expectedMethod = 'GET'` cho list → **POST `/admin/api/secrets` bị 405 trước khi tới nhánh `create`** (dead code ở `upstreamPath`, dòng 172-175 cũ).
- Fix: dispatch method ngay trong `handleSecretsRoute` qua `effectiveRoute` — `list+GET → list`, `list+POST → create`, mọi cặp khác → 405. Các bước validate/upstream phía dưới dùng `effectiveRoute`.
- Không đổi contract/wire; không sửa file nào khác; probe focused transient (đã xoá sau khi chạy) chứng minh POST tới đúng upstream create, GET giữ list, PUT/DELETE/PATCH → 405.

## 2. Fix (chỉ `secrets.ts`)

Thay gate `expectedMethod` bằng method dispatch tường minh:

```ts
let effectiveRoute: SecretsRoute;
if (route.kind === 'list') {
  if (method === 'GET') effectiveRoute = route;
  else if (method === 'POST') effectiveRoute = { kind: 'create' };
  else { writeProblem(res, 405, 'METHOD_NOT_ALLOWED', ...); return; }
} else if (method === 'POST') {
  effectiveRoute = route;
} else {
  writeProblem(res, 405, 'METHOD_NOT_ALLOWED', ...);
  return;
}
```

Sau đó dùng `effectiveRoute` cho: list branch (`:136`), `validateMutation` (`:178`), `upstreamPath` (`:189-191`). Không đổi thứ tự auth/tenant-scope/CSRF/body validation; mutation vẫn platform-admin + CSRF + schema như cũ.

Ma trận hành vi sau fix:

| Request | Kết quả |
|---|---|
| `GET /admin/api/secrets` | list (upstream `GET /api/v1/admin/secrets`) |
| `POST /admin/api/secrets` | **create** (upstream `POST /api/v1/admin/secrets`, body đã gắn tenant scope) |
| `PUT/DELETE/PATCH /admin/api/secrets` | 405 `METHOD_NOT_ALLOWED` (không gọi upstream) |
| `GET /admin/api/secrets/:id/rotate|disable|test` | 405 |
| `POST /admin/api/secrets/:id/rotate|disable|test` | mutation như cũ (validation → upstream) |
