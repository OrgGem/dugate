## 1. Patch đã áp (`artifact-read-decrypt.ts`, hunk duy nhất của lane này)

```diff
 function mapCryptoError(error: unknown): never {
   if (error instanceof HttpError) throw error;
   if (error instanceof CryptoStorageError) {
+    // RFX-08 / verify F1: a size refusal is a policy decision, not an
+    // authentication verdict. The facade throws SIZE_LIMIT for both the eager
+    // decryptStream check and the mid-stream backstop, and deliberately
+    // re-throws it instead of relabelling - flattening it here told the caller
+    // a perfectly authentic artifact was unauthentic. TOO_LARGE is the
+    // published public code for 413 (PublicErrorCodes, errors.ts:34).
+    if (error.code === 'SIZE_LIMIT') {
+      fail(413, 'TOO_LARGE', 'encrypted artifact exceeds the maximum decryptable size');
+    }
     // AUTHENTICATION_FAILED covers a wrong key, a tampered body, and a context
     // (tenant/artifact/version) that does not match. They are deliberately
     // indistinguishable to the caller: telling them apart turns the endpoint
     // into an oracle for probing which part of the binding was wrong.
     fail(503, 'STORAGE_FAILURE', 'encrypted artifact could not be authenticated');
   }
   fail(503, 'STORAGE_FAILURE', 'encrypted artifact could not be read');
 }
```

## 4. Ghi chú & finding phụ

1. **`STORAGE_FAILURE` không nằm trong `PublicErrorCodes`** (finding phụ từ F1 §3): grep `errors.ts` chỉ có `TOO_LARGE`; **`STORAGE_FAILURE` xuất hiện 0 lần trong `packages/contracts`** — tức code chưa publish đang nằm trên public surface (nhánh auth 503 của file này, và nhiều chỗ khác). **Không sửa** theo đúng dispatch. Khuyến nghị: reconcile riêng — nếu đổi, phải giữ tính **anti-oracle** (mọi auth failure dùng CÙNG một code/message; không tách wrong-key vs tamper vs mis-binding) và cân nhắc cả các call-site `STORAGE_FAILURE` khác trong cây trước khi thêm vào contracts.
2. **Nhánh auth giữ nguyên** — ngoài phạm vi (dispatch ghi rõ); regression guard ở §2 khoá lại đúng message/status cũ.
3. **Mid-stream backstop chưa được drive riêng qua consumer**: `validateManifest` ghìm tổng size theo chunk nên backstop gần như không thể chạm qua `decryptStoredArtifact`; eager path đã chứng minh seam mapping, còn backstop được cover ở tầng facade (`crypto-storage-plaintext-bound.test.ts`). Giới hạn này giống F1 §7 — live S3/Vault vẫn chưa chạy.
4. **Wire status đổi có chủ đích**: artifact quá ngưỡng giờ trả **413 TOO_LARGE** (không còn 503) trên 2 route gọi consumer — worker read `server.ts:1674`, public download `server.ts:2211`. 413 là non-retryable theo semantics; đúng mục tiêu F1 (không còn báo "unauthentic" cho artifact authentic).
5. **File dùng chung với lane RFX-05**: `artifact-read-decrypt.ts` trong working tree còn các hunk CÓ TRƯỚC của lane khác (`readManifest(…, versionId?)` + `manifestVersionId`) — lane này **không chạm** các hunk đó; delta của lane đúng bằng khối `mapCryptoError` ở §1.
