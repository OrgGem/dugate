## 3. Mock-service wiring and rework test double

`MOCK_SERVICE_URL` is read in the legacy seed module with default `http://localhost:3099`; `connectorUrl(slug)` maps seeded connections to `/ext/<slug>` (`lib/db/seed.ts:8-11`). The seed writes that URL into each `ExternalApiConnection.endpointUrl` (`lib/db/seed.ts:321-339`), including the `sys-assistant` and `ext-prompt-wizard` rows (`lib/db/seed.ts:257-287`).

The normal request path does not read `MOCK_SERVICE_URL` directly: submission enqueues an operation job (`lib/pipelines/submit.ts:336-351`), and the engine later looks up connection rows by processor slug and uses their endpoint configuration (`lib/pipelines/engine.ts:264-269,307-359`). Therefore production execution can depend on the mock service indirectly when its database contains seed-generated mock endpoint URLs, but the worker path itself is configured through connection rows rather than that environment variable (`lib/db/seed.ts:8-11,321-339`; `lib/pipelines/engine.ts:264-269,307-359`).

The mock service fakes connector results by slug, accepts scenario/delay controls, uses in-memory multipart file handling, and reports file metadata rather than processing actual bytes (`mock-service/routes/connectors.js:11-12,14-45,57-80,83-115`). Its map enumerates 18 response modules, while the health route advertises 15 connector slugs (`mock-service/routes/connectors.js:14-34`; `mock-service/routes/health.js:13-31`).

Rework has a test-only provider double, not an equivalent standalone legacy mock HTTP service: `MockProvider` supports success, rate-limited, malformed, async, and network-cut modes, and its unit test constructs it directly (`du-rework/services/connector/tests/mock-provider/provider.ts:3-18`; `du-rework/services/connector/tests/mock-provider/provider.test.ts:1-10`). The production connector entrypoint instead composes real identity/grant verification, credential encryption, and provider-host configuration; no `MOCK_SERVICE_URL` is wired there (`du-rework/services/connector/src/entrypoint.ts:7-27`).

## 5. Rework gaps and behavior at risk

No UI/API surface is proposed `cutover-required` until product ownership and dependency are known. If sign-off retains any workflow UI, rework already exposes encrypted upload initialization/content and operation list/detail routes (`du-rework/services/orchestrator/src/server.ts:1442-1481,1766-1804,1806-1825`), but the searched route dispatcher has no legacy `/api/v1/docs/workflows` process multiplexer; an unmatched path reaches its 404 response (`du-rework/services/orchestrator/src/server.ts:1189-1197,2746`). The three legacy UI page routes are not in the rework admin router; its matcher handles admin root/login/logout, audit/crypto paths, then configured generic sections and returns `null` when unmatched (`du-rework/services/orchestrator/src/app/admin/shell-router.ts:465-511`). No chat or prompt-wizard page is present in the searched admin source (`du-rework/services/orchestrator/src/app/admin/shell-router.ts:465-511`).

Rework connector has a generic invocation API rather than the legacy demo endpoints: its HTTP server parses `POST /invocations` and invokes the connector runtime (`du-rework/services/connector/src/http/server.ts:303-312`). The searched connector source has no homepage chat, prompt wizard, LC-checker, document pipeline UI, or legacy mock-service HTTP dispatcher; its provider fake is confined to tests (`du-rework/services/connector/src/http/server.ts:149-158,290-312`; `du-rework/services/connector/tests/mock-provider/provider.ts:3-18`).

If the `RETIRE` proposal is accepted for the legacy mock service, local/default seed connections would lose their `/ext/:slug` responder and its canned assistant, prompt-wizard, and document-connector responses; the mock route stores uploads only in memory and records file metadata rather than actual content (`lib/db/seed.ts:8-11,257-287,321-339`; `mock-service/routes/connectors.js:11-12,57-70,103-115`; `mock-service/responses/sys-assistant.js:3-29`; `mock-service/responses/ext-prompt-wizard.js:23-61`). Rework's test `MockProvider` covers provider transport outcomes, but it is not wire-compatible with those legacy `/ext/:slug` response builders (`du-rework/services/connector/tests/mock-provider/provider.ts:3-18`).
