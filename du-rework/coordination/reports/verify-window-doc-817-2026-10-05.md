# VERIFY-WINDOW-DOC-817 — independent source check of ENCMETA-WINDOW-DESIGN-808

**Scope:** Read-only review of `coordination/reports/encmeta-window-design-808-2026-10-05.md` against current orchestrator source and the in-tree adjudication receipts for A11, A12, A13, A15 and A17. No source or design document was edited; no tests, database, Vault, commit or task tick were performed.

## Verdict

The 808 document is a design proposal, not an implemented control plane. Several primitives and the authenticated census exist, but the production switch, injected reader, backfill command, metrics and runtime expiry enforcement do not. Two consequential design claims are stale or incomplete: the literal-`true` inventory is **8 sites, not 6**, and the shown authenticated-gate call omits the independent tenant census required for `PASS`.

## Adjudication cross-check

- **A11 — authenticated read, not just envelope shape.** The counter now opens shape-pass values using `readStoredText(..., false)` or `readStored(..., false)` and counts auth/context/other failures as blockers (`metadata-auth-counter.ts:281–305,320–321`). This implementation exists; a target DB result does not.
- **A12 — two gates, production scope, operator decision.** The A12 runbook requires shape census first, then authenticated reads on the production key and exact row binding; it also records that nothing in that packet had yet run against the project DB/Vault (`a12-auth-gate-runbook-808:38–49,64–75`). The 808 design preserves the two-gate idea but its code example omits the tenant census now required by A17.
- **A13 — BA-01/BA-02/BA-05 implementation.** The in-tree review roll-up maps A13 to these fixes (`coordination/reports/claude.md:1878–1882`); current source contains the TEXT dispatch, strict text parsing and exact-eight guard cited above. I found no standalone ENCMETA A13 adjudication file; other `D-EVID-A13` mentions concern unrelated documentation work.
- **A15 — no-seam wrapper.** The wrapper now calls the shared `assertReadableWithoutSeam` before returning an unsealed value (`runtime.ts:468–479`); `readStoredText` uses the same guard (`metadata-crypto.ts:416–420`). The guard rejects envelope-shaped values, but deliberately permits non-envelope plaintext without a seam; it is not the proposed global plaintext-mode switch.
- **A17 — census completeness.** The current counter requires exact eight-slot coverage and a supplied, non-empty expected tenant census for a passing gate (`metadata-auth-counter.ts:58–74,342–388`). The PG16 evidence is a disposable fixture only; it does not certify production rows, production RLS or Vault (`gate-coverage-817:28–32`, `full-regression-815:55–59`).

The source tree contains five direct `false` arguments in these paths: `runtime.ts:361`, `ingestion-consumer.ts:340`, `metadata-auth-counter.ts:291,297`, and the nested sealed-text open at `metadata-crypto.ts:427`. The design’s two-category inventory describes the intended policy boundary, but it is not a complete literal-boolean inventory.

## Claims that remain unproven or need correction in the design

1. Correct the site count to eight and include both `mappers.ts` result-ref and `ingestion-consumer.ts` payload-ref reads; re-inventory again immediately before implementation because the tree has moved since 808.
2. Add the independent expected tenant census to the A17 gate invocation and define how census completeness is established. `countUnsealedWithAuth({db, crypto})` is not a passing call under the current API.
3. Distinguish implemented library primitives from runtime enforcement. Today there is no metadata read policy, no CLI, no production backfill caller, no reader injection, no metrics, and no switch to expire/fail-close all reader paths.
4. Correct the six-slot storage-type statement: one of the six non-result-ref slots is TEXT (`step_checkpoints.output_ref`); five are JSONB.
5. Reconcile §5: automatic expiry and “both close paths require operator env change/restart” cannot both be true. Specify separately the automatic helper deadline and the user-authorized config flip, then show the code path that enforces each.
6. Document the no-seam case explicitly. The current helper allows unsealed plaintext when no seam exists; passing `false` at the crypto API does not protect a caller that skips that API or returns via the no-seam branch.
7. Bound “fixed and verified” statements to the available offline/disposable evidence. No target production database, independent target tenant census or Vault provider run was found in these receipts.

**Conclusion:** The design’s reusable window and authenticated-counter primitives are real, and A11/A13/A15/A17 code fixes are visible. The key user-facing promise—one boot policy that controls every plaintext read, times out the production window, emits progress, and can safely flip all readers to fail-closed—is not present in current source; the document must remain labelled as a proposal until that wiring and the target A12/A17 evidence exist.
