## TenantSelect follow-up — 2026-10-08

Integration was inspected and stopped before product edits because the existing component cannot preserve the required tenant-session prefill behavior:

- `components/ui/tenant-select.tsx` accepts `value: string | null`, `onValueChange(value: string | null)`, optional `allowAll` (default `false`), and `disabled`. It loads the roster itself, renders a selected value only when that ID exists in the loaded roster, and returns `null` only for the optional All entry. Platform session selection and locking can use this API without enabling All.
- `services/orchestrator/src/app/admin/bff/handle.ts` restricts `GET /admin/api/tenants` to `role === 'admin'` and `principal.kind === 'platform'`. A tenant-scoped session cannot load that roster, so TenantSelect enters its unavailable state and clears the displayed selection even when Usage passes the session's `tenantId` as `value` and sets `disabled`.
- The component has no prop for injecting a current tenant option/name or using a caller-provided option list. Adding such a prop would change the other agent's component scope, so it was not modified. Usage integration remains pending that component capability/contract.

No code files changed in this follow-up. Typecheck and tests were not run because the component contract blocks an implementation that meets the stated semantics. Earlier implementation and its test receipts above are unchanged.
