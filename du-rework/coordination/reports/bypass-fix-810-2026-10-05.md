## 1. BA-01 — the important one

### 1.1 The defect

`step_checkpoints.output_ref` is a **TEXT** column. The writer stores `JSON.stringify(sealedOutputRef)` (`runtime.ts:730`). The reader passed that TEXT straight to `openMetadata` → `crypto.readStored(value, context, true)`, and `readStored` treats **any string as unsealed** — it returns it **verbatim, with no AEAD open**.

Consequence: a valid envelope and a **tampered** envelope were equally readable, and both surfaced as a raw JSON string instead of the ref.

The auth counter did not share this bug — it uses `readStoredText(..., false)`, which parses and opens. That mismatch is exactly what the packet asked to remove.

### 1.2 The fix

`openMetadata` now dispatches on the value type:

```ts
if (typeof value === 'string') return readStoredText(crypto, value, context, true);
return crypto.readStored(value, context, true);
```

Strings (the TEXT columns) get parsed + AEAD-opened on the same binding the writer used; parsed jsonb values keep the existing path. Reader and counter now read the same shape — pinned by `reader and auth counter read the SAME shape`.

### 1.3 The trap the packet warned about, and how it was avoided

`allowPlaintext` was **left at `true`**. Flipping that boolean without the decode is the destructive move: `readStored` on a string with `allowPlaintext=false` throws `NOT_SEALED`, so a **valid** TEXT envelope would be rejected and the flip would break real data. The decode came first; the boolean did not move. The ENC-09 window is still open, which is correct — the A2 flip was not this packet's call.

`openMetadata` was exported (one word) so this fix is directly testable rather than only reachable through a deep service call.

### 1.4 Evidence

Mutation probe: reverting the string dispatch turns **4 of 13** tests RED, and the received value is the raw envelope JSON:

```
Expected: "artifact://checkpoint-out"
Received: "{\"version\":1,\"algorithm\":\"aes-256-gcm\",\"keyRef\":\"bypass-fix-810\",...}"
```

That is the pre-fix behaviour reproduced exactly. Mutation reverted; `grep MUTATION` over `runtime.ts` is clean.

## 2. BA-02 — `readStoredText` silent pass-throughs

| Was | Now |
|---|---|
| `typeof value !== 'string' → String(value)` (returns `"[object Object]"`) | `INVALID_INPUT` — a jsonb value belongs to `readStored` |
| `!crypto → return value` | if the string parses to something that **looks like an envelope**, `KEY_PROVIDER_FAILED`; otherwise the legacy plaintext passes through |
| `String(opened)` on a non-string result | `INVALID_INPUT` |

**Reasoning on the no-seam case, stated plainly:** making *every* no-seam read fail closed would break a deployment that has never sealed anything, and would contradict `sealMetadata`/`openMetadata`, which both return verbatim without a seam. So the tightening is targeted at the genuinely dangerous case — a **sealed** row being read by a deployment that cannot open it. That is the same treatment `openDispatchSourceUrl` already gives it (`ingestion-consumer.ts:319-321`), which keeps the module internally consistent.

A new module-level `looksLikeEnvelope` mirrors the `isSealed` discriminator so the no-seam check needs no seam.

## 3. BA-05 — the gate can no longer be run on a subset

`countUnsealedWithAuth` now calls `assertFullCoverage(specs)`: coverage must be an **exact** set match against the eight `METADATA_SLOTS` — no missing, no extra, no duplicates, and the count must match. Previously a caller could pass a trimmed list and get `GATE PASSES` for slots nobody counted.

Tests prove a **trimmed** list and an **empty** list are both rejected with a message naming what is missing.

## 6. BA-04 — warned, not fixed (out of lease)

`openDispatchSourceUrl` (`ingestion-consumer.ts:317-318`) returns **any string before touching the crypto**:

```ts
if (typeof raw === 'string') return raw;
```

Same shape as BA-01: if `sourceUrl` ever arrives as a JSON **string** holding a sealed envelope, it is returned as that raw string, and a tampered one is returned too. Today the submit side seals `sourceUrl` inside the jsonb `outbox.payload`, so the string branch is reached only by a legacy plaintext writer — which makes it a latent defect rather than a live one.

`ingestion-consumer.ts` is **not** in this packet's leases, so it is reported rather than edited. **Recommendation:** give the string branch the same treatment BA-01 just got — route a string that parses to an envelope through the crypto, keep a non-envelope string verbatim. The fix is small and mirrors `openMetadata`.
