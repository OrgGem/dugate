- Stub: `tests/browser/admin-web/harness.ts:721-727` returns
  `{tenantId, from, to, requests: 12, tokens: 3456}`.
- Parser needs: `totals{operations,inputTokens,outputTokens,pages,costMicrousd}` + strict `rows[]`
  (`overview-screen.tsx:81-136`).
- Consequence in the real browser run: the tile correctly renders `unavailable` +
  "The admin API returned an unreadable usage summary." / `UNREADABLE_RESPONSE` (screenshot
  `raw/overview-01-ready.png`, taken by the spec run). **No fabricated numbers** — fail-closed works.
- The spec still passes because it only asserts `getByText('Usage rollup')` visibility, not totals.
  Therefore browser green **proves the real read is wired** (5 stub calls with session tenant + auth, §1)
  but does **not** prove real totals rendering in the browser. Fixing this means updating the browser-lane
  stub (and ideally adding a totals assertion) — outside this verify lane's read-only scope, reported as
  requested.
