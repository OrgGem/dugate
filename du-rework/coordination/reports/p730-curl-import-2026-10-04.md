## 2. Parser contract (`curl-import.ts`)

Pure text. No shell execution, no `fetch`, no `eval`, no child process — the leaf imports nothing at all.

**Supported:** `-X/--request`, `-H/--header`, `-F/--form`, `--url`, `-d/--data/--data-raw/
--data-binary/--data-urlencode`, bare `http(s)://` argument, single/double quoting, `\`+newline
continuation, `curl` token skipped (case-insensitive).

**Hard limits (`CURL_IMPORT_LIMITS`, line 21):** 65,536 input chars · 512 tokens · 32 headers ·
32 form fields · 8,192 value chars · 2,048 URL chars · 16 method chars. Each one **fails** the parse
(`*_TOO_LONG` / `TOO_MANY_*`); nothing is truncated.

**19 error codes + 6 note codes**, all messages generated from a fixed table plus a token index.
Legacy reference for parity: `app/api-connections/page.tsx:87` `parseCurl`.

**Two-shape secret discipline (the load-bearing design choice):**
- `CurlImportDraft` carries `auth.secretValue` — the apply path needs it to prefill the credential
  editor. In-memory only.
- `CurlImportSummary` carries **no secret and no header value at all**. It is the only shape the
  preview renders, so nothing in it can be logged or persisted.

## 4. Security posture (all verified, not asserted — see §5)

- **No execution.** Parser imports nothing; `eval(`, `new Function`, `child_process`, `execSync`,
  `fetch(`, `XMLHttpRequest` are absent from both leaves (checked against source text).
- **No persistence.** The preview contains no `localStorage`, `sessionStorage`, `indexedDB`,
  `document.cookie`, `console.` or `fetch(`; the paste lives in component state only.
- **No echo of the paste.** Error and note text comes from a constant table; a malformed paste
  containing a secret cannot be echoed back into the UI, a log or a receipt (case 13 proves it).
- **Redaction shape.** Secret headers and secret-named form fields show `****` + last 4 chars;
  non-secret headers show `set (N chars)` and no value; the auth secret shows a fingerprint only.

**Residual risk stated plainly:** `isSecretTokenName` matches an exact list plus fragments
(`secret`, `password`, `token`, `credential`, `signature`, `api-key`, …). A form field with an
unknown secret name (`session-id` is the verified example) is shown in the preview. Header values
are never shown regardless of name, so the exposure is limited to form-field values.

**Also stated plainly:** the controlled `<textarea>` renders the operator's own paste into the DOM.
That is the input field, not the preview — the verification in §5 measures the two separately.
