## 3. Recommended single choke point for `file_urls`

Put the only `file_urls` resolution path in the COMP-03 public `POST /api/v1/docs/{service}` facade, **after authentication/tenant and endpoint-profile resolution and multipart/field parsing, but before the operation is submitted or any raw URL can be forwarded**. The existing legacy decoder only proves that `file_urls` is an array of URL-shaped entries (`services/orchestrator/src/compat/legacy-wire-decoders.ts:403-423`); `validateSourceUrl` applies only to the separate top-level `sourceUrl`, so neither check covers these entries.

At that choke point, treat every entry as untrusted and use the shared `createPinnedFetch` default policy for the initial URL and each bounded manual redirect hop. Do not inject raw global `fetch`, enable private-network access from request data, forward a URL to a connector, or add a caller-controlled trust/disable flag. Apply configured URL credentials only after preserving the destination policy, stream under per-file/aggregate byte and time limits, validate filename/MIME/extension, send the fetched bytes through the existing encrypted public-upload pipeline, wait for a `READY` artifact acknowledgement, and submit only tenant-scoped `artifactIds`.

This is the point where the facade still knows the authenticated tenant, selected endpoint/profile policy, legacy field shape, and can prevent all later branches from receiving raw URLs. The source URL ingestion fence is for a distinct `sourceUrl` contract; the upload gateway validates uploaded `mimeType`/`fileName`/`sizeBytes` metadata (`modules/public-api/upload-encryption-gateway.ts:711-732`) but does not fetch or adjudicate a URL; connector-level checks cannot protect the orchestrator from a URL fetch delegated downstream. A `file_urls` bridge that routes around this facade or goes directly to the storage grant/upload or connector path would leave an SSRF bypass.

**Conclusion:** `@du/egress` is enforced for source acquisition, webhook delivery, and connector provider transport only. The other listed network paths either rely on platform-configured destinations, have URL-syntax-only checks, are dormant, or perform presigned artifact transfer; none supplies a guard for legacy `file_urls` entries today.
