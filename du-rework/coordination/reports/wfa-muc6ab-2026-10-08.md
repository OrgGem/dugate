## 6a — file-backend output answered 404 `No Output`

**Symptom**: `loadLegacyOutput` only served `output_content`; a row with `output_file_path` returned `null`, which the mount reports as 404 `No Output`.

**Fail-first test** (`tests/wfa-api-lifecycle.test.ts` › `WFA legacy operation lifecycle adapters › serves a file-backend output by reading its artifact blob`):
- row: `output_content: null`, `output_file_path: 'art-output-1'`, terminal `SUCCEEDED`;
- fake `artifacts.getBlob` returns `Readable.from(['# file backed'])`;
- assert bytes === `# file backed` and `getBlob` called with `'art-output-1'`.

**RED (pre-fix)**: `exit=1` — `Tests: 2 failed, 42 passed, 44 total`.
Failure: `expect(bytes?.toString('utf8')).toBe('# file backed')` → `Received: undefined` (i.e. the mount would answer 404 `No Output`).

**Fix**:
- `toLegacyRow`: `outputFilePath: text(row.output_file_path)`;
- `loadLegacyOutput`: order is inline (`output_content`) → file backend (`output_file_path`) → `null`;
- the file reference is opened through the platform's server-side blob reader (`ctx.artifacts.getBlob`), the same store the canonical download route uses, and collected into a `Buffer` (`collectOutputBytes`);
- an unreadable reference returns `null`, so the mount keeps the documented 404 `no-output` in the legacy problem+json shape. The legacy route's separate 404 `file-not-found` for a broken reference is intentionally collapsed — this host contract has one absent-output signal, not two (documented in the function comment).

**GREEN**: `exit=0` — 2 suites, `45 passed, 45 total`; per-test JSON evidence: 5/5 named tests passed.

## 6b — `GET /api/v1/services` answered 500

**Symptom**: `host.serviceCatalogue` unwired → `internalError` 500.

**Fail-first test** (`tests/legacy-http-mount.test.ts` › `legacy mount — billing and discoverability › answers 200 with an empty service list when the catalogue is not wired`):
- host without `serviceCatalogue`;
- expects 200, `services: []`, legacy Vietnamese message.

**RED (pre-fix)**: `exit=1` — failure `Expected: 200 / Received: 500` at `legacy-http-mount.test.ts:446`.

**Decision (packet asks to state which path)**: **trả empty list khi chưa có catalogue** — `host.serviceCatalogue?.(...) ?? []`. Chosen because no trustworthy catalogue source exists on this compat host in this slice (profile-lock/registry data is not available here), and the acceptance requires discovery to answer. A wired host is unchanged: the existing test `serviceCatalogue: () => [{ serviceId: 'extract' }]` still returns its list with 200.

**Fix**: `const catalogue = host.serviceCatalogue?.(principal.apiKeyId) ?? [];` — the `internalError` branch is removed; the interface comment documents the fallback.

Also updated `tests/rv01-loopback-http-offline.test.ts`: the test asserting `answers 500 while unwired, never an empty catalogue` now asserts 200 + `services: []` (targeted run green, 1 passed / 47 skipped).
