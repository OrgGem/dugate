# UBW-08-PRE — UI architecture readiness and traceability review

Date: 2026-10-09
Scope: `du-rework` only. This is a read-only architecture and documentation review. It does not grant implementation leases, approve a gate change, certify UI behavior, or replace the later independent functional/browser verdict.

## Readiness verdict

**Not ready for parallel implementation dispatch as written.** The architecture has a coherent direction for alias-first process binding, dynamic business discovery, same-business workflows, and a separate workflow-profile adapter. The evidence and proposed packets still leave decisions open and have concrete same-file lease overlaps. The current Workflows UI also contradicts the earlier claim that the closed gate is data-free. These issues need to be resolved in the packet contracts and exclusive leases before affected work is dispatched.

Section 6 has a case mapped to each of its nine acceptance bullets, but several mappings are conditional rather than executable acceptance: workflow cases depend on explicit `Δ-DEV-03` authority; business deactivation/drain and wait/resume semantics remain open; the profile upgrade/rollback path lacks an explicit verification case; and the Admin Web browser harness has no exact file lease. Those rows must remain skipped or not run until their stated prerequisites are met. A skip is not a pass.

The path inventory below is a reconciliation of *proposed* leases in UBW-02 through UBW-06. Per canonical plan §5, these are not active grants; a dispatcher must refresh the live roster and issue exact dispatch proof. Static review found collisions even before live-lease status is considered.
