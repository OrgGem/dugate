## 1. The defect and the fix

Before:

```ts
if (typeof raw === 'string') return raw;   // <-- any string, envelope or not
```

After:

```ts
if (typeof raw === 'string') {
  const parsed = safeDispatchSourceUrlJson(raw);
  if (parsed === undefined) return raw;    // PLAINTEXT lane — unchanged
  raw = parsed;                            // envelope-shaped string -> PROTECTED lane
}
```

`safeDispatchSourceUrlJson` is the door: it parses the string and returns the object only when it carries the envelope shape (`version===1`, `algorithm==='aes-256-gcm'`, string `ciphertext`, object `dek`, string `nonce`, string `tag`). It never throws — a malformed string is treated as plaintext.

**Item 2 — the two lanes, stated:**

| lane | input | behaviour |
|---|---|---|
| PLAINTEXT | a string that is not envelope-shaped | returned verbatim (legacy / no-seam) |
| PROTECTED | a parsed object, OR a string carrying an envelope | AEAD-opened on `(tenant, 'tasks.payload_ref', taskId)` |

**Item 4 — the legitimate path is preserved.** A backfill feeding its first copy, or a deployment with encryption simply off, writes a value that was never sealed. That is not envelope-shaped and still passes through verbatim — pinned by `a plaintext value with NO seam still passes` and `a plain URL string passes through verbatim`.

## 3. Item 3 — the outbox writer is NOT the defect described

The packet says `submission.ts:535` writes a plain `BusinessJobV1` envelope. **It does not.**

`submission.ts:388` calls `sealOutboxSourceUrl(metadataCrypto, submission.sourceUrl, ctx.tenantId, rootTaskId)`, and `sealOutboxSourceUrl` (`submission.ts:167-180`) returns `crypto.seal(sourceUrl, { tenantId, slot: 'tasks.payload_ref', refId: rootTaskId })` — the envelope **OBJECT** — which is then embedded in the outbox payload JSON at `:535`.

So the writer already seals. The consumer's `rawSourceUrl` (`ingestion-consumer.ts:580`, `payload.sourceUrl`) is an **object**, which takes the object path and AEAD-opens correctly.

**Consequence: no separate task is needed for the writer.** The only live gap was the string branch, which this packet closes. The packet's premise was inaccurate; recorded here so a follow-up is not opened against a non-defect.
