## 2. Fixture explicit — per-suite namespace, không singleton chéo file

`createRuntimeFixture({ suite })` trong harness cấp **cho mỗi file**: isolation context riêng (schema `du_test_<runId>` / Redis DB index / artifact dir — qua `tests/isolation/namespace`), **businessId riêng `test-biz-<runId>-<suite>`**, token riêng, `port: 0`, app riêng, queue drain riêng. Vì mỗi file gọi `createTestIsolationContext` → runId riêng theo mặc định; khi operator pin `TEST_RUN_ID`, hậu tố `-suite` vẫn bảo đảm rows/version/queue **không đè nhau**.

- **`scopedCleanup` chỉ có MỘT bản** (harness), parameterized theo fixture; chỉ `DELETE ... WHERE business_id=$1` + `business_versions WHERE business_id=$1` — không TRUNCATE/flushdb; teardown chỉ `DROP SCHEMA IF EXISTS "<schema riêng>" CASCADE` + artifact dir của chính nó.
- Boot/teardown per-file (trước: 1 lần cho cả file): `autoMigrate: true` như các live suite khác (`usage-summary`, `ingress-bounded`, …) — mặc định mỗi file schema riêng nên không chồng migration; khi pin `TEST_RUN_ID` (semantics của framework, không phải per-file) migrate idempotent theo `schema_migrations`.
- Mỗi file khai `let app/baseUrl/queueName` riêng, gán trong `beforeAll` của chính nó — không singleton chia sẻ giữa các file.
