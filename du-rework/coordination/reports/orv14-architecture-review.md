## Storage, maintenance and availability invariants

**Storage generation router:** backend generation is distinct from object version and encryption key version. Add server-owned generation ID to persisted artifact location and encrypted manifest binding, with a compatibility map for existing static-backend rows. Resolve reads/deletes via exact generation+object version; every encrypted sidecar, multipart checkpoint, ingestion cache/output and worker gateway follows that pin. `forGeneration()` must not fall back to current generation. Stage probes use isolated namespace and real reader/writer identity, HeadBucket and bounded encrypted write/read/hash/delete. Publish only after required consumers acknowledge; failure keeps previous active generation and draft. Rollback selects a prior write generation while retaining both generations' readers, including objects created during partial activation. Do not retire credentials with remaining refs or late lease/HITL/retry readers. Generation router ownership remains solely host lane; settings injects/control-commands it.

**Durable jobs:** use PG intent+outbox+audit transaction and typed fixed owner adapters; reuse the proven Compose idempotency/claim/START ACK/report-hash/UNKNOWN pattern where a host effect is nontransactional. State version, target revision, preview fingerprint/expiry, stable cursor and per-item exact request/outcome keys are mandatory. Jobs survive process restart. Completed retry replays exact ACK; divergent report409. A lost execution acknowledgement remains UNKNOWN/holds the relevant fence until owner evidence reconciliation. Never retry an uncertain provider invocation or host command automatically. Safe DB-local jobs may resume unprocessed items after rechecking eligibility; an item whose external delete outcome is uncertain is reconciled by exact version HEAD/absence, not blindly counted deleted twice.

**Cleanup/recovery:** dry-run freezes intended bounded candidate set and counts but deletion rechecks under DB claim/fence immediately before the exact-version storage call. Protect operation/task/HITL/artifact/cache refs, active leases, retries, multipart and backup pins. Block new reference acquisition on deletion-claimed artifact in the same authoritative service transaction; restore eligibility if no delete occurred. Terminal operation soft delete does not erase audit or every artifact. Runtime expired-lease recovery reuses existing epoch fence/cancel-aware method; failed webhook retry reuses frozen delivery ID/payload/cap. Broker/outbox reconciliation operates authoritative delivery IDs and dedup, not queue purge or duplicate business submit.

**Queue controls/drain:** platform-only for shared queue; a granted tenant operator sees only its projections and can operate only assigned operation lifecycle. Durable pause blocks new dispatch/claim, leaving accepted queued operations discoverable; admission-maintenance is a distinct503/Retry-After mode. Per-worker/version DRAINING blocks fresh claims even on another Orchestrator replica; active heartbeat/complete/checkpoint remain allowed. SDK pauses consumers without hot-loop redelivery. Drain completes only on fresh observed control revision and authoritative zero active leases, with cancellation/checkpoint states accounted. Timeout stays DRAINING/PARTIAL, not fake drained; no force kill of active leases. Resume advances revision and releases queued delivery once. Use consistent lock order for control→worker→operation→task and owner fencing to avoid drain/claim races.

**Backup/restore:** existing `infra/scripts/backup-postgres.sh` and `restore-postgres.sh` already use named protected libpq services, checksum, no overwrite and isolated `du_restore_` target guard. Wrap fixed approved versions/paths through dedicated manifest executor, not browser-provided env/path/command. Persist backup bundle ID, DB schema/migration/config/Connector ledger watermark, exact S3 generation/version manifest, crypto key/secret-ref versions and authorized encrypted key escrow references. Backup mount encryption must be evidenced, not assumed from variable name. Cross-plane consistency requires controlled admission/dispatch/poll/usage fence and reconciled watermark; PG dumps alone do not capture S3/Vault/Connector state. Restore first into a new isolated DB/storage generation with dispatch/provider calls disabled; hash/count/decrypt/login/old download checks, idempotency/reservations/UNKNOWN reconciliation precede cutover. Implement controlled confirmed cutover/rollback boundaries, while customer production execution waits for its actual data/credentials/ingress receipt. Do not pretend application rollback reverses DB writes.

**Availability:** extend trusted manifest with two explicit deployment slots and an approved fixed ingress adapter/config; slot services, immutable image/config digest, readiness probes and rollback edges are allowlisted. Start inactive slot, verify every required replica and shared dependency/config generation, drain affected worker instances preserving leases, then atomically change fixed ingress generation and verify requests before old slot retirement. Failed readiness/switch rolls back ingress and retains serving slot; job exposes each replica desired/observed ACK/PARTIAL. Rehearse actual long operations/HITL/callback/provider uncertainty through switch and restart with no lost/duplicate effect. A replica replacement alternative must prove equivalent minimum-ready and lease guarantees; plain Compose up-all/restart is not accepted as HA. Never assert zero downtime just because two synthetic containers run.

## Rich usage/budget and incident invariants

Rich event producer must carry actual attempt/step/tenant/operation/task/business/profile/Connector/account/model facts from authenticated request/grant and immutable operation pin. Duration is measured from real invocation start/completion, not operation-wide fabricated time. Snapshot validated price revision at invocation/reservation; a later price change produces a separate projection/repricing view, not alteration of ledger event. Provider usage missing is pending/unpriced with unknown price provenance, not measured zero. Preserve retry/event identity and transactional usage outbox; dedup across delayed delivery/restart. Historical BASIC rows remain useful and truthfully nullable; do not pass them through a strict rich projector by filling invented attribution.

Select active persisted budget policy revision server-side for tenant/key/profile/business/calendar window; lock quota scope before provider request and use existing reserve/settle/reconcile. Running/UNKNOWN retains reservation; settled usage releases once, late event dedup prevents double total. Suspend/publish/rollback budget is CAS+audit. Define aggregation of simultaneous scopes (all applicable limits must allow), inherited legacy opening balance vs new events, timezone/day/month boundaries and warning thresholds. UI shows committed vs held vs unpriced/pending and persisted budget status; filters, bounded export and drilldown retain tenant/time scope. No platform bearer or browser-defined budget bypass.

### Budget parent/child policy decision and exact consumer signature

Coordinator/integration owner identified a one-budget effective lookup that could let a specific child policy bypass a tenant cap. **APPROVED decision: enforce ALL applicable active published tenant/key/profile/business budgets atomically.** COST-04 defines optional narrower scopes but does not authorize discarding a parent cap. This extends the existing durable engine; it must not become multiple independently committed `reserve()` calls.

Freeze injected lookup as `getEffectiveBudgets({ tenantId, apiKeyId, profileId, businessId, at }): Promise<EffectiveBudgetPin[]>`, with each pin `{ budgetId, revision, config, quotaScopeKey, periodStart, periodEnd }`. Owner may change identifier spelling through the shared-contract handoff, but cardinality and semantics are mandatory. Budget windows remain canonical UTC daily/monthly `[start,end)`; a UI timezone changes display/filter interpretation, not quota calendar silently.

Add one logical `BudgetReservationGroup` for actual tenant/operation/task/invocation/attempt and N child quota-hold rows (unique group+budget+period). Pins are exact immutable budget IDs/revisions; locks are deterministic sorted stable quota/window keys, acquired in one PostgreSQL transaction. Re-evaluate all applicable published caps under those locks, then commit all holds or no holds/provider call. Stable quota identity excludes mutable threshold/revision so publishing a new cap does not reset committed use or erase old held reservations. Any applicable blocking policy BLOCK wins; alert-only breaches warn without discarding a blocking parent. Superseded revisions' active holds remain counted until settlement/reconciliation under the relevant stable quota/window.

One usage event links to one logical settlement/group identity; preserve the existing one-event/one-reservation dedup invariant at that boundary. Settle/release all child holds once in the same transaction and append immutable per-budget evaluations; do not call the current single-reservation `reconcile()` separately for the same event where its unique indexes prohibit that. Running/UNKNOWN retains every child hold. Divergent retry409, exact retry same group/outcomes. Evaluation/UI returns per-budget decisions and one invocation decision; overlapping budget totals must never be summed into a duplicated monetary ledger total. Required concurrency negatives: parent exhausted/child available, child exhausted/parent available, opposite-order concurrent groups, atomic failure after one planned hold, duplicate/late settlement, policy revision change while held and UNKNOWN evidence recovery.

Incident detection derives from real health/queue/lease/Connector/usage signals and persisted threshold revision. Dedup by stable scope/entity/rule fingerprint, append recurrence/history; acknowledgement is distinct from signal recovery/resolution. Assign owner via authorized identity lookup. Resolve requires fresh recovered signal and owner reconciliation/backlog checks or records remaining uncertainty explicitly; user cannot mark an UNKNOWN invocation successful. Suppression has scope/TTL/reason and audit without erasing history. Connector owns provider evidence reconciliation with state/version/ref/amount safety; incident service coordinates that owner result. Incidents/Overview link entity→operation→invocation→Connector→audit within three navigation steps.
