## Detailed Requirements

### 1. PC-R04: Fingerprint Contracts Extension
In `du-rework/orchestrator/packages/contracts/src/profile-groups.ts`:
- Extend `ResolutionFingerprintPartsV2`:
  ```typescript
  export interface ResolutionFingerprintPartsV2 {
    tenantId: string;
    apiKeyId: string;
    groupId: string;
    groupRevision: number;
    accessVersion: number;
    function: ProfileGroupResolutionFunctionRefV2;
    children: readonly ProfileGroupChildPinV2[];
    /** AI settings revision (legacy or partitioned). */
    tenantDefaultsAiRevision: number | null;
    /** Prompt settings revision. */
    tenantDefaultsPromptRevision: number | null;
    /** Snapshot / digest of tenant defaults if available. */
    tenantDefaultsDigest?: string | null;
    connectorBindings: readonly ProfileGroupConnectorBindingRefV2[];
    workflow: { slug?: string; revision: number; digest: string } | null;
    submission: Submission;
    /** Backward compatibility: if tenantDefaultsRevision was provided, map it to tenantDefaultsAiRevision. */
    tenantDefaultsRevision?: number | null;
  }
  ```
- In `computeResolutionFingerprint(parts: ResolutionFingerprintPartsV2)`:
  - Include `tenantDefaultsAiRevision` (or `parts.tenantDefaultsRevision ?? null`), `tenantDefaultsPromptRevision: parts.tenantDefaultsPromptRevision ?? null`, and `tenantDefaultsDigest: parts.tenantDefaultsDigest ?? null` in the hashed payload.
  - If `workflow` is present, include `{ slug: parts.workflow.slug, revision: parts.workflow.revision, digest: parts.workflow.digest }`.
- Ensure changing prompt revision produces a different fingerprint!

### 2. PC-R07: Parameter Resolution in ProfileGroupFunctionSchema

- Export relevant types `ParameterSource`, `ParameterResolution`.
