## Mục tiêu
Implement một `runChunk` production-quality cho doc-compare, dùng đúng runtime/connector pattern mà
document-core đã có (xem `worker.ts` root handler dispatch và `task-context` connector invocation).

1. Tạo runtime thật (khuyến nghị file mới
   `businesses/document-core/src/pipelines/workflows/doc-compare/runner.ts`) export
   `createDocCompareRuntime(...)` trả về object thỏa `DocCompareRuntime` với `runChunk` chạy được.
2. `runChunk(spec: ChunkTaskSpec)` với `spec.stage ∈ {'compare-structure','compare-references'}`:
   - gọi connector qua đúng interface mà lane đã dùng cho 33 test (KHÔNG hard-code model/prompt ngoài
     module);
   - trả `ChunkOutcome` đúng shape: `{chunkId, status:'succeeded'|'failed', evidence?, error?}`;
   - **fail-closed**: connector lỗi / trả thiếu field / timeout ⇒ `status:'failed'` + `error` mang code
     hợp lệ của module, **không bao giờ** mark `succeeded` với evidence bịa ra;
   - giữ nguyên `assertNoIdentityLeak` (từ chối `apiKeyId/tenantId/userId/authorization/role` trong
     payload) — nếu connector trả identity field ⇒ fail.
3. Test mới cho runner thật (dùng mock connector như 33 test cũ): ≥3 case — success cấu trúc, success
   tham chiếu, connector fail ⇒ `failed` (không succeeded).
4. Không đổi hành vi của 33 test hiện có; resume/parallel không hồi quy.
